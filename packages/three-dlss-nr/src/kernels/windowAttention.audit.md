# Audit: composed `attend_window_tiled` -> `windowAttention.ts`

Line-by-line map from the reference's composed window attention (OpenDLSS-NR by maan, MIT, `9d08f41`,
`ports/browser-webgpu/src/window/variants.js` `windowAttentionCode()`, prepended with `enable f16;` and
`shaders/numerics.wgsl` by `window/index.js`) to the TSL in `windowAttention.ts`. Dump the composed text with

```sh
node -e "import('./reference/OpenDLSS-NR/ports/browser-webgpu/src/window/variants.js').then(m => console.log(m.windowAttentionCode()))"
```

(its hash is pinned by `test/reference/composedWgsl.test.ts`). "Same" means the same operations in the same order on
the same values; every deviation is listed with the reason it cannot change a byte.

Evidence: `windowAttention.gpu.test.ts` checks the TSL against `test/oracle/attention.ts` (an independent CPU port of
the composed WGSL) on 13 cases (every phase, partial edge windows, heads 1/2/16, all-zero and tiny tokens) and 16 vs
32 queries per workgroup; `test/browser/windowAttentionChrome.mjs` runs the composed reference itself in Chrome
(D3D12 + DXC, `shader-f16`, RTX 3060 Ti) on the same 13 inputs: all bit-exact against the oracle. The in-suite
reference-parity variants run wherever Dawn has `shader-f16`.

## Notation

- Half operations. The reference computes in `f16`; the TSL computes in f32 and rounds to half. For `+ - * / sqrt`
  of halves the f32 result rounded to half equals the correctly rounded half result (f32 has p = 24 >= 2 * 11 + 2), and
  products of two halves are exact in f32. `f16(x)` of an f32 is `nrRoundHalf(x)`.
- `nrRoundHalf(x)` == `round_f16(x)` == `f16_to_f32(f16_bits(x))`; `nrPublishE4Value(x)` == `publish_fp8(x)` ==
  `decode_e4m3(encode_e4m3(f16_bits(x)))`; `e4Code(x)` == `publish_e4_code(x)` == `encode_e4m3(f16_bits(x))`
  (`attentionNumerics.ts`; the first two proven equal to the spelled-out forms over every half, every half midpoint and
  its f32 neighbours and 2^18 random f32 patterns by `attentionNumerics.gpu.test.ts`).
- Since `f16_bits(round_f16(x)) == f16_bits(x)` for every f32 (the half of a half is itself; NaN maps to a NaN either
  way, and `encode_e4m3` maps every NaN to 0), `publish_fp8(f32(f16(a) * f16(b)))` == `nrPublishE4Value(a * b)`.

## `tiled_score`, `tiled_softmax_pair`, `tiled_softmax_sum` -> phase 4

| composed WGSL                                                                                                        | TSL                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `tiled_score(query, index)` = `vector_scores[query * 16 + index / 4][index % 4]` (physical index)                    | `s(index)` = `nr_window_k[lane * 16 + (index >> 2)][index & 3]`                                                 |
| `blocks01 = s[key] + s[key+8]` ... `blocks67`; `((blocks01 + blocks23) + blocks45) + blocks67`, every `+` a half add | loop `m` 0..3: `pair = halfFold(m == 0, pair, halfAdd(s(key + 16m), s(key + 16m + 8)))` - the same left fold    |
| `even = ((p(0,0) + p(1,0)) + p(2,0)) + p(3,0)`, `odd` likewise, `even + odd`                                         | loops `p` 0..3 (`halfFold`) inside `parity` 0..1 (`halfFold`)                                                   |

`halfFold(first, sum, value)` is `first ? value : halfAdd(sum, value)`: on the first step it is the value itself, so the
fold starts exactly where the reference's parenthesization starts.

## Memory and threads

24576 bytes of workgroup memory at 32 queries (q 4096 + k 8192 + v 8192 + packed_k 2048 + packed_s 2048), the
minimum `createNRDevice` requires, against the reference's ~19.3 KB of halves (it needs 32 KB only because it
requests it). 16 queries: 256 invocations, 21504 bytes. Lifetimes: `nr_window_k` holds the norm lanes (phase 1),
then K (2-3), then the scores (4) and weights (5-6); `nr_window_v` holds the norms (1-2), then V (3-6); `nr_window_q`
holds Q (2-3), then the reciprocals (4-5). Each reuse is separated from the last read of the previous contents by a
barrier.

## Codegen notes (FXC)

Fixed-count reductions and the per-lane `vec4` builds are WGSL loops (`forRange`) rather than JS-unrolled code, and
every half rounding is `nrRoundHalf` rather than `nrRoundF16`: FXC (D3D12 without DXC) inlines every function call,
and the fully unrolled form took 53 s to compile one shape; this form takes about 2 s (Vulkan well under 1 s).
