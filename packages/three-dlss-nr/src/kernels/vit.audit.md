# Audit: `shaders/vit.wgsl` -> `vit.ts`

Line-by-line map from the reference's ViT attention (OpenDLSS-NR by maan, MIT, `9d08f41`,
`ports/browser-webgpu/shaders/vit.wgsl`, prepended with `shaders/numerics.wgsl`, module override `PADDED_TOKENS`) to
the TSL in `vit.ts`. Notation as in `windowAttention.audit.md`: `nrRoundHalf` == `round_f16`, `nrPublishE4Value` ==
`decode_e4m3(encode_e4m3(f16_bits(x)))`, `e4Code` == `encode_e4m3(f16_bits(x))` (`attentionNumerics.ts`, checked
exhaustively); every other helper is the foundation's port of `numerics.wgsl` (`tsl/numerics.ts`).

Evidence: `vit.gpu.test.ts` checks both kernels against `test/oracle/attention.ts` (64 tokens; 96 -> 128 with padding;
72 -> 128 with 20 % zero and 20 % tiny tokens) and, where vit.wgsl compiles, against the reference itself. On the dev
machine vit.wgsl does not compile under FXC (`normal_exponent`'s `bitcast<u32>(abs(x))`, R16), so the reference
variants skip on the default D3D12 backend; with `DLSS_NR_DAWN_BACKEND=vulkan` (vulkan-1.dll beside dawn.node) all
three reference-parity cases run and are bit-exact for both `vit normalized` (whole allocation, padding rows zero) and
`vit attended`.

## Codegen notes (FXC)

The reference's straight-line reductions are WGSL loops here and half roundings use `nrRoundHalf`: compiled
literally (16-term reductions and two `vit_norm` calls inlined), FXC took about 4 s for `vit_normalize`; this form
takes under 1 s for each kernel.
